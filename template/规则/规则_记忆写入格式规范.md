# 记忆写入格式规范

> 索引：[[记忆索引]] ｜ 路由：[[路由索引]]

本规则适用于所有通过 MCP 读写本记忆库的 AI 工具，包括 Codex、Claude
Desktop、WorkBuddy、Cursor 等。

## 核心原则

1. **能更新就不新建**：写入前先 `memory_search` 查重，找到已有条目就更新
2. **source 必须填写**：每次 `memory_write` 传 `source`，值用你的工具身份，
   如 `codex` / `claude` / `workbuddy` / `cursor`
3. **标签复用**：先用 `memory_list` 看已有标签，保持全小写英文、不发明同义词
4. **正文第一段是摘要**：自然语言概述本条记什么，不要用标题或分隔符开头
5. **正文从 H1 开始**：`content` 只给正文，不要带 YAML 头；frontmatter 由
   server 统一维护

## 目录结构与路由

默认记忆库在 `~/ai-memory`，可用环境变量 `AI_MEMORY_DIR` 指向任意目录。
笔记按“领域目录 + 路由索引”两级结构存放：

```text
ai-memory/
├─ 记忆索引.md            # MOC：自动维护，按类型分组的全量索引
├─ 路由索引.md            # 自动维护：先在这里定位，再按需读叶子
├─ 近期工作动态.md        # 只留最近 7 天，超期滚入 日志/
├─ 项目状态.md            # 各项目状态总表
├─ 规则/                  # 规则_*：长期使用与写入规范
├─ 项目/                  # 项目_*：按项目主题的长期笔记
├─ 人设与偏好/            # 用户画像、AI人格 等身份与偏好
├─ 知识/                  # 知识_*：调研、对比、排障等知识叶子
└─ 日志/                  # 工作动态_YYYY-MM.md：月度历史时间线
```

server 在 `memory_write` 时会按标题前缀自动放入对应目录：

| 标题前缀或标题 | 目标目录 |
| --- | --- |
| `规则_` | `规则/` |
| `项目_` | `项目/` |
| `知识_` | `知识/` |
| `用户画像` / `AI人格` | `人设与偏好/` |
| `日志_` / `工作动态_` / 日期开头 | `日志/` |
| 其他 | 库根 |

库根只放 4 个系统页，不要放业务叶子。目录用于人眼浏览；AI 先读
[[路由索引]] 定位，再按需 `memory_read`，省 token 且不容易迷路。

## 标题与文件名规范

- 标题 == 文件名（去扩展名），双链 `[[标题]]` 必须逐字一致
- 只用中文、字母、数字、括号 `( )` 和下划线 `_` 做分隔；禁用 `/`、`\`、
  空格、`:`、`*`、`?`、`"`、`<`、`>`、`|` 等文件系统特殊字符
- 标题尽量唯一且稳定，便于按标题 upsert，不要频繁改名
- server 有消毒兜底，但不要依赖它；人工建文件时主动遵守规范

## 字段规范

- `title`：必填，含义明确，项目用 `项目_` 前缀、规则用 `规则_` 前缀
- `tags`：建议填写，全小写英文，复用已有标签体系
- `source`：必填，标识写入方身份
- `summary`：建议填写，一段可读摘要；否则路由索引的摘要列会空白
- `content`：第一段写摘要，正文用 Markdown，关联笔记用 `[[标题]]` 双链，
  单篇太长时拆成多篇

## MCP 同步节奏

完成一项实质工作（技术决策、修 bug、项目进展、新偏好、用户说“记住”）后：

1. 先 `memory_search` 查重，能更新就不新建
2. `memory_write` 写入或更新笔记，传 `source` 与 `summary`
3. 在 [[近期工作动态]] 的当天 `## YYYY-MM-DD` 区块追加一行摘要
4. 如果涉及项目，同步更新 [[项目状态]] 中对应行

## 什么时候写 / 什么时候不写

| 场景 | 动作 |
| --- | --- |
| 完成技术决策 | 写入或更新项目页 |
| 修了一个 bug | 写 `知识_` 或 `修复_` 记录，同时更新项目页 |
| 分享了偏好/设定 | 更新 `用户画像` 或对应偏好页 |
| 明确说“记住” | 写入一条记忆 |
| 每天结束 | 更新近期工作动态 |
| 只是闲聊 | 不写 |

## 维护规则

- 长期结论回流到项目页/规则页，不要只写进时间线
- 过时信息在原条目标注有效日期，不直接删除
- 重复内容合并到最完整的一条，其余软删除
