# ai-memory-template 使用教程

> 面向第一次接触这套系统的人。目标是让你在 10 分钟内拥有一套可被多个 AI
> 工具读写、能放进 Obsidian 浏览、能用 git 同步的长期记忆库。

## 0. 先理解三个概念

**知识库（vault）**：一个以 Markdown 为主的目录。你的记忆就是一篇篇带
frontmatter 的 `.md` 文件，可以用 Obsidian、VS Code、任何文本编辑器打开。

**MCP（Model Context Protocol）**：AI 工具读取外部工具/数据的开放协议。本
项目的 `server.py` 是一个 MCP 服务器，通过 stdio 与 AI 客户端通信，提供
`memory_write`、`memory_search` 等 20 个工具。

**两级检索**：知识库根目录只放 4 个系统页；业务笔记按领域放进
`规则/ 项目/ 人设与偏好/ 知识/ 日志/`。AI 先读紧凑的 `路由索引` 定位笔记，
再按需读取叶子笔记，而不是每次扫描全库。

这套结构适合以下场景：

- 你有多个 AI 工具（Codex、Claude、WorkBuddy、Cursor 等），希望它们共享
  长期记忆和项目上下文
- 你想用 Obsidian 的图谱功能可视化“笔记之间的关系”
- 你想把个人知识库放进 git，实现多设备同步和历史追溯
- 你想先复制一套“只有规则、没有内容”的知识库，再按自己的习惯填充

## 1. 环境要求

- Python 3.10+
- 支持 MCP 的 AI 客户端（Codex CLI/桌面端、Claude Desktop、WorkBuddy、
  Cursor 等）
- 可选：Obsidian（用于可视化浏览）、git（用于同步）

如果电脑还没有 Python，请先安装，并确保终端里能运行 `python --version`
（Linux/macOS 通常是 `python3`）。

## 2. 部署方式

### 方式 A：让 AI 帮你部署（推荐给不熟悉命令行的用户）

把下面整段发给任意一个 AI 助手：

```text
请帮我部署 ai-memory-template。仓库地址：
https://github.com/Learnbout/ai-memory-template

1. 克隆或下载项目
2. 安装依赖：pip install mcp
3. 在我的电脑上创建 ~/ai-memory 记忆库
4. 把 template 目录里的文件、目录以及 server.py 复制到 ~/ai-memory
5. 按我的操作系统配置 MCP，让我可以使用 memory_write / memory_search 等工具
6. 配置完成后读取 ~/ai-memory/规则/ 里的规则文档，并把验证方法告诉我
```

### 方式 B：一键安装脚本

Linux / macOS：

```bash
git clone https://github.com/Learnbout/ai-memory-template.git
cd ai-memory-template
bash install.sh
```

Windows PowerShell：

```powershell
git clone https://github.com/Learnbout/ai-memory-template.git
cd ai-memory-template
.\install.ps1
```

脚本默认把知识库建在 `~/ai-memory`。想放到别处：

```bash
bash install.sh ~/my-brain
```

```powershell
.\install.ps1 -TargetDir D:\my-brain
```

脚本会做四件事：

1. 检查 Python 并安装 `mcp`
2. 创建记忆库目录
3. 把 `template/` 里的空结构复制进去
4. 把 `server.py` 复制进去，并打印 MCP 配置

### 方式 C：手动部署

如果你希望完全理解每一步，可以手动执行：

```bash
git clone https://github.com/Learnbout/ai-memory-template.git
cd ai-memory-template
pip install mcp

# Linux/macOS
mkdir -p ~/ai-memory
cp -R template/. ~/ai-memory/
cp server.py ~/ai-memory/

# Windows PowerShell
mkdir "$HOME\ai-memory"
Copy-Item "template\*" -Destination "$HOME\ai-memory" -Recurse
Copy-Item server.py -Destination "$HOME\ai-memory\server.py"
```

手动部署后，知识库目录应至少包含：

```text
ai-memory/
├─ 记忆索引.md
├─ 路由索引.md
├─ 近期工作动态.md
├─ 项目状态.md
├─ 规则/
│  ├─ 规则_记忆写入格式规范.md
│  └─ 规则_Git版本控制规范.md
├─ 项目/
├─ 人设与偏好/
├─ 知识/
├─ 日志/
└─ server.py
```

## 3. 配置 AI 工具

每个 AI 客户端只需配置一次。核心是：让客户端启动 `server.py`，并把
`AI_MEMORY_DIR` 指向你的记忆库目录。

下面例子假设记忆库在 `~/ai-memory`（Windows 是
`C:\Users\你的用户名\ai-memory`），请替换成自己的实际路径。

### Codex

编辑 `~/.codex/config.toml`：

```toml
[mcp_servers]
[mcp_servers.ai-memory]
command = "python"          # Windows 上可能是 python.exe 的完整路径
args = ["/home/you/ai-memory/server.py"]
env = { AI_MEMORY_DIR = "/home/you/ai-memory" }
```

### Claude Desktop

编辑 `claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "ai-memory": {
      "command": "python",
      "args": ["/home/you/ai-memory/server.py"],
      "env": { "AI_MEMORY_DIR": "/home/you/ai-memory" }
    }
  }
}
```

Windows 路径中的反斜杠在 JSON 里要写成双反斜杠：

```json
{
  "mcpServers": {
    "ai-memory": {
      "command": "C:\\Users\\you\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
      "args": ["C:\\Users\\you\\ai-memory\\server.py"],
      "env": { "AI_MEMORY_DIR": "C:\\Users\\you\\ai-memory" }
    }
  }
}
```

### WorkBuddy

WorkBuddy 的 MCP 配置通常位于 `~/.workbuddy/mcp.json`，需要带
`"type": "stdio"`：

```json
{
  "mcpServers": {
    "ai-memory": {
      "type": "stdio",
      "command": "python",
      "args": ["/home/you/ai-memory/server.py"],
      "env": { "AI_MEMORY_DIR": "/home/you/ai-memory" }
    }
  }
}
```

### Cursor

编辑 `~/.cursor/mcp.json`：

```json
{
  "mcpServers": {
    "ai-memory": {
      "command": "python",
      "args": ["/home/you/ai-memory/server.py"],
      "env": { "AI_MEMORY_DIR": "/home/you/ai-memory" }
    }
  }
}
```

配置完成后重启 AI 客户端，让新的 MCP 服务器生效。

## 4. 用 Obsidian 浏览知识库

1. 打开 Obsidian
2. 选择 “打开文件夹作为仓库”
3. 选择 `~/ai-memory`（即记忆库根目录）
4. 打开左侧的 `记忆索引.md` 或 `路由索引.md`

Obsidian 原生支持 `[[双链]]` 和 YAML frontmatter，所以你能看到：

- 图谱视图：笔记之间的引用关系
- 局部图谱：某篇笔记的出链和反向链接
- 文件资源管理器：按领域目录浏览

Obsidian 会在目录下创建 `.obsidian/` 配置目录。它不应被写进 git，模板的
`.gitignore` 已处理过；如果你为自己的记忆库新建 git 仓库，请同样忽略它。

## 5. 验证 MCP 是否工作

在 AI 对话中依次执行：

1. `memory_stats`：应返回笔记数量、标签、访问热度等统计
2. `memory_list`：应列出 记忆索引、路由索引、近期工作动态、项目状态
3. `memory_search`，关键词 “记忆”：应能搜到规则文档
4. `memory_write`，标题 `用户画像`，内容写一段你自己的简介
5. `memory_read`，标题 `用户画像`：应读到刚写的内容

如果第 4 步成功，观察知识库目录，会发现 `用户画像.md` 被自动放进了
`人设与偏好/`，`记忆索引.md` 和 `路由索引.md` 也自动更新了。

## 6. 第一次使用的推荐流程

部署并验证后，建议按这个顺序把知识库变成“你自己的”：

1. 写 `用户画像`：你的称呼、领域、常用工具、语言偏好
2. 建第一篇项目笔记，例如 `项目_第一个AI辅助项目`，写下目标与约束
3. 在 `项目状态` 表里加一行，链接到这篇项目笔记
4. 把每次完成的实质工作追加到 `近期工作动态` 的当天
5. 遇到可复用的经验时，写 `知识_xxx`（例如 `知识_如何配置MCP`）

可以直接对 AI 说：

```text
帮我初始化记忆库：
1. 先读 记忆索引 和 规则/ 里的规范
2. 用 memory_write 创建一篇 用户画像，内容是我提供的基本信息
3. 用 memory_write 创建一篇 项目_我的第一个项目
4. 更新 项目状态 和 近期工作动态
5. 完成后告诉我记忆库现在有哪些笔记
```

## 7. 目录与规则详解

### 四个系统页（只放库根）

| 文件 | 用途 | 谁维护 |
| --- | --- | --- |
| `记忆索引.md` | 按类型分组的总索引 | server 自动 |
| `路由索引.md` | 每条笔记一行：标题/目录/日期/标签/摘要 | server 自动 |
| `近期工作动态.md` | 最近 7 天的时间线 | 你和 AI 每次写完更新 |
| `项目状态.md` | 项目状态总表 | 你和 AI 按项目变更更新 |

### 领域目录

| 目录 | 放什么 | 命名 |
| --- | --- | --- |
| `规则/` | 长期有效的写入/使用规范 | `规则_xxx.md` |
| `项目/` | 按项目主题的长期笔记 | `项目_xxx.md` |
| `人设与偏好/` | 用户画像、AI 人格等身份设定 | `用户画像.md`、`AI人格.md` |
| `知识/` | 调研、对比、排障、教程等知识叶子 | `知识_xxx.md` |
| `日志/` | 月度历史时间线 | `工作动态_YYYY-MM.md` |

### 最重要的写入规范

完整规范在记忆库的 `规则/规则_记忆写入格式规范.md`。核心几条：

1. 写之前先搜，能更新就不新建
2. `memory_write` 必须传 `source`（`codex` / `claude` / `workbuddy` /
   `cursor` 等）
3. 标题 == 文件名；只允许中文、字母、数字、括号和下划线；禁用空格与 `/`
4. `content` 从正文开始写，不要带 YAML 头
5. 写完业务笔记后，顺手更新 `近期工作动态`，涉及项目再更新 `项目状态`

## 8. 日常维护

### 时间线瘦身

`近期工作动态.md` 只保留最近 7 天。超过 7 天后：

1. 新建 `日志/工作动态_YYYY-MM.md`
2. 按 `## YYYY-MM-DD` 分区，把过期的条目移过去
3. 清空 `近期工作动态` 里已滚动的旧条目

可以让 AI 定期执行，例如每月第一天：

```text
把 近期工作动态 里超过 7 天的条目滚动到 日志/工作动态_YYYY-MM.md，
月份文件不存在就新建，最后更新 路由索引 指向。
```

### 冷数据归档

server 提供 tier 和归档机制：

- `memory_archive(title)`：把某篇笔记正文移入 `.archive/`，原位留摘要 stub
- `memory_archive_old(days=90)`：批量归档 90 天未更新的笔记（自动跳过核心页）
- `memory_restore(title)`：从 `.archive/` 恢复
- `memory_heat_suggest()`：按访问频次与陈旧度给出 tier 调整建议

### 定期体检

- `memory_audit()`：检查空壳文件、死链、命名漂移、缺 source/tags 的笔记
- `memory_rebuild_links()`：重扫所有笔记正文，刷新 frontmatter 的 `links`
- `memory_orphans()`：找出没有被其他笔记引用的孤立笔记

## 9. git 同步与多设备

知识库是普通文件，随时可以 `git init`：

```bash
cd ~/ai-memory
git init
git add -A
git commit -m "chore: 初始化记忆库"
```

如果你想同步到 GitHub：

```bash
# 先在 GitHub 创建一个空仓库（不要勾选自动生成 README）
git remote add origin https://github.com/你的用户名/ai-memory.git
git branch -M main
git push -u origin main
```

其他设备上：

```bash
git clone https://github.com/你的用户名/ai-memory.git ~/ai-memory
```

给每个 AI 客户端配置 MCP 时，把 `AI_MEMORY_DIR` 指向这台设备上的记忆库目录。
提交信息建议使用统一格式：

```text
codex: 更新项目_部署方案 - 完成架构决策
claude: 新增知识_如何配置MCP - 记录配置步骤
```

注意：不要把个人敏感信息（token、密钥、密码）提交进 git。

## 10. 自定义

### 改记忆库路径

不运行安装脚本时，通过环境变量指定：

```bash
AI_MEMORY_DIR=/path/to/my-vault python /path/to/server.py
```

```powershell
$env:AI_MEMORY_DIR = "D:\my-vault"
python D:\my-vault\server.py
```

### 改自动标签

编辑 `server.py` 中的 `_TAG_AUTO_MAP`，它是“正文关键词 -> 标签”的映射表，
约 30 条。按你的领域增删即可。

### 改目录路由

编辑 `server.py` 的 `_folder_for_title()`，决定标题前缀映射到哪个目录。

### 改核心页保护名单

编辑 `server.py` 顶部的 `CORE_PAGES`。归档、孤儿检测会跳过这些页面。

### 模板更新

如果模板仓库发布了新版本，你可以只替换 `server.py`，也可以对比
`template/规则/` 中的规则文件，保留你自己的内容。

## 11. 常见问题

### AI 客户端说找不到 server.py？

确认 MCP 配置里的 `args` 指向实际存在的 `server.py` 完整路径。Windows 上
还要确认 `command` 用的是完整 Python 路径（例如
`C:\Users\you\AppData\Local\Programs\Python\Python312\python.exe`），而不是
系统商店里不带界面的 python stub。

### 启动时报 `ModuleNotFoundError: No module named 'mcp'`？

在启动 server 的同一个 Python 环境里执行 `pip install mcp`。如果 AI 客户端
用的是虚拟环境，请给同一个虚拟环境的 Python 安装依赖。

### 我的笔记没有出现在 `记忆索引`？

先确认文件在记忆库目录下且是 `.md`。`server.py` 只扫描记忆库内的 Markdown，
并排除 `.archive/ .trash/ .git/ .obsidian/ __pycache__/` 等系统目录。如果
规则或代码改动后没刷新，重启 AI 客户端，或调用 `memory_rebuild_links`。

### 我可以只做纯文本知识库，不接 MCP 吗？

可以。整个目录就是普通 Markdown，你可以只保留 `template/` 的结构与规则，
不运行 server，完全手写维护。MCP 只是让 AI 读写更方便的附加层。

### `.obsidian/`、`.archive/`、`.trash/` 需要提交吗？

不需要。`.obsidian/` 是 Obsidian 本地配置，`.archive/` 与 `.trash/` 是归档
和回收站。它们应留在本地或在 `.gitignore` 中排除。
