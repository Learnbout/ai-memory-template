# ai-memory · 让你的 AI 记住你

> 一句话：**它是一本放在你自己电脑或自己服务器上的「记忆本」**，
> 你用过哪个 AI、说过什么、定过什么规矩，它都替你记着；
> 下次换一个 AI、换一个对话，翻一下这本笔记就能接着干。

不用注册，不用上传到别人家，笔记就是一堆普通文件，躺在你自己的硬盘里。

---

## 一、它解决什么问题（说人话）

平时用 AI 有个很烦的地方：**它像每天换一个临时工。**

今天这个不知道昨天那个干了啥，你每次都得重新交代一遍：我是谁、我用什么技术栈、上次那个 bug 怎么修的、这个项目叫什么名字、别用什么写法……

这个项目就是给这些临时工配一本**大家都得翻、也都得写的交接笔记**：

- 干活前先翻笔记，不用你重复讲背景；
- 干完把新发现写回去，明天来的那个接着用；
- 笔记本在你自己的硬盘上，不上传、不联网也能用。

## 二、装好之后你能干什么

| 能干的事 | 说人话 |
|---|---|
| 让 AI 自己查你的笔记 | 在 Cursor / opencode / Codex 里说"查一下我之前的偏好"，它自己去翻 |
| 网页上看、搜、改 | 浏览器打开工作台，能搜、能编辑、能看历史版本 |
| 全文检索 | 中英文混着搜都行，不用记确切标题 |
| 笔记互相引用 | 像维基百科那样一路点下去 |
| 版本历史 | 每改一次都留底，改坏了能翻回去 |
| 多人一起用（可选） | 装在服务器上，给同事开账号，带聊天和操作记录 |

## 三、两种装法：**装哪个包就是哪种，不用你选**

| | **只有我自己用**（本地版） | **我和同事一起用**（中心化版） |
|---|---|---|
| 装在哪 | 你的电脑 | 一台一直开着的电脑或服务器 |
| 要登录吗 | **不要**，打开就能用 | 要，装的时候你自己设管理员账号 |
| 数据在哪 | 你的硬盘 | 那台服务器上 |
| 外面能访问吗 | 不能，只听本机 | 能，同事用浏览器连 |
| 多出来的东西 | 没有聊天、没有管理后台 | 有聊天、账号管理、操作记录 |

**判断标准就一句**：你自己一个人用，还是别人也要看？前者本地版，后者中心化版。

## 四、怎么装（三种方式，挑一种）

### 方式 1 · Windows：双击安装包（最省事）

下载 `ai-memory-installer-local.exe`（自己用）或 `ai-memory-installer-central.exe`（一起用），双击。

安装器是个**普通的 Windows 窗口**，一路点「下一步」就行，它会：

1. 先检查这台电脑（运行环境、磁盘、要用的端口、上面装了哪些 AI 工具）
2. 问你把笔记放哪个文件夹（默认已经填好，直接下一步就行）
3. 问要不要**自带运行环境**（默认要，这样不用你另外装 Python、也不用联网）
4. 列出它在你电脑上找到的 AI 工具，勾上的它帮你接好
5. 装完直接把工作台给你打开

**不需要你先装 Python**，因为运行环境已经打包在安装包里了。
装完想搬走？把整个文件夹拷到别的电脑就能用；想彻底删掉？删文件夹就等于卸干净。

### 方式 2 · 命令行（Linux / macOS / 想在 Windows 上手动装）

```bash
./install.sh              # 自己用
./install.sh --central    # 和同事一起用
```

不带参数直接跑，它会问你一句"这份装给谁用"，回车就是"自己用"。
它会建一个独立的运行环境（不污染你系统的 Python）、装好依赖、建一个空库、把服务起起来。

### 方式 3 · 服务器上装成系统服务

```bash
sudo ./deploy-server.sh --dry-run   # 先预演，看它打算做什么（不改任何东西）
sudo ./deploy-server.sh             # 真装
```

它会：建一个不能登录的系统用户来跑服务（不用 root 跑）、把代码装到 `/opt/ai-memory`、
装好依赖、建库、**把笔记数据库权限设成只有服务能读写**、生成并启动 systemd 单元。

**已经装过的机器上，它默认不会覆盖你现有的服务配置**（会备份并告诉你需要 `--force`）。

## 五、能接哪些 AI 工具

装的时候它会自动扫你电脑上有什么，勾上的它帮你把配置写好（**改之前先备份**）：

WorkBuddy、Claude Code、Claude Desktop、Codex CLI、Cursor、Windsurf、Gemini CLI、
Qwen Code、Cline、**opencode**、DSH（这个要手动加，格式比较特殊）。

接上之后，AI 通过 MCP 协议用 `http://127.0.0.1:8770/mcp` 读写你的笔记。

## 六、你的笔记存在哪、怎么备份

- **笔记**：一个普通文件夹，里面是普通的文本文件，记事本能打开，`git` 也能管
- **默认位置**：安装器会问，Windows 上默认在 `%LOCALAPPDATA%\ai-memory` 下
- **备份**：整个文件夹拷走就是备份
- **卸载**：删掉安装文件夹就等于卸载；卸载时它会问你要不要保留笔记

它**不会**做的事：不写注册表、不改系统 PATH、不动你已有的 Python 环境、不覆盖你已有的笔记。

```
ai-memory/                  ← 装到哪就是这个目录
├── backend/                工作台的后端
├── frontend/dist/          工作台的页面（已经构建好，不用装 Node）

│   └── 数据库/index.sqlite3
├── .runtime/               自带的运行环境（便携用；用系统 Python 装则没有这个）
└── .ai-memory-install.json 安装清单：版本号 + 每个文件的校验值
```

## 八、常见问题

**问：装完 AI 还是读不到我的笔记？**
先看两个端口通不通：工作台 `http://127.0.0.1:8787/`、AI 用的 `http://127.0.0.1:8770/mcp`。
两个都通的话，在 AI 里说一句"用记忆库查一下我之前的偏好"，它应该能列出工具。

**问：端口被占了怎么办？**
安装器会自己换一个号，不用你操作。如果 8787 上已经有一个旧的工作台在跑，
它会告诉你"这台电脑上已有工作台"，而不是偷偷把旧的那个当成新的打开。

**问：能不能装在 U 盘里带着走？**
可以。选"自带运行环境"这一路，装完整个文件夹拷到 U 盘就能在别的电脑上用。

**问：多人版和单人版能互相切换吗？**
能，用另一个安装包装一遍就行。它会认出来"这台电脑上已经装过另一个版本"，
原来的笔记不会被动。

**问：我的笔记会被上传吗？**
不会。默认所有东西都在本机，连安装都是离线的（运行环境打包在安装包里）。
只有你自己把它装到服务器上、并且开了对外的门，别人才能访问。

## 九、开发者看这里

```
graphite/backend/      工作台后端（FastAPI）
graphite/frontend/     工作台前端（React + Vite，dist 是预构建产物）
vault/                 库本体：MCP 服务、检索、数据库、脚本
installer/             安装器：原生 WinForms 向导 + 命令行版 + 打包脚本
```

用到的技术：Python 3.12、FastAPI、SQLite（含 FTS5 全文索引）、React、.NET WinForms（安装器界面）、MCP 协议。

想自己打包安装器：

```bash
installer\.venv\Scripts\python.exe 工具\build_release.py    # 一条命令出三个 exe
```
